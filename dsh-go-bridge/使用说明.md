# dsh-go 桥接服务

给 AstrBot 插件用的一条通道。AstrBot 装在别的 Linux 环境（比如安卓「泡泡版」App 自带的容器）里，
那边没有 `dsh`，就由这个服务在这边代跑。

## 启动

```sh
sh 启动.sh
```

输出示例：

```
桥接服务已启动
地址：http://127.0.0.1:6799
口令：uemX-GW-nCde4XvWN0gEtVu_
```

把这**地址**和**口令**填进 AstrBot 插件的 `bridge_url` 和 `bridge_token`。

## 检查

```sh
TOKEN=$(cat /root/.dsh-bridge-token)
curl -s -H "X-DSH-Token: $TOKEN" http://127.0.0.1:6799/health
```

返回 `"engine": "idle"` 或 `"connected"` 就正常。

## 试一条指令

```sh
TOKEN=$(cat /root/.dsh-bridge-token)
curl -s -X POST -H "X-DSH-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"text":"只回复：通","session":"test"}' \
  http://127.0.0.1:6799/ask
```

## 日志

```sh
tail -f /root/dsh_bridge.log
```

## 停止

```sh
pkill -f "dsh_bridge.py"
```

## 自动启动（已配置好）

**不用手动管了。** 每次 DSH 引擎启动，会自动把这里拉起来：

- 挂在 `~/.dsh/profiles/web/cordis.patch.yml` 的 `dsh-go-bridge-autostart` 插件
- 插件本体：`/root/dsh-go-bridge-autostart.mjs`
- 效果：打开 DSH App（引擎启动）→ 桥接服务自动跑起来

三重兜底：

1. 引擎启动时自动拉起（主）
2. 打开 DSH 终端时 `.bashrc` 钩子检查一次（辅）
3. 手动 `sh 启动.sh`（兜底）

插件设计成"绝不抛异常"：即使脚本或插件文件出问题，也只记一行日志，
不会让 DSH 引擎起不来（已实测：插件文件缺失时引擎仍正常启动）。

## 接口一览

| 路径 | 作用 |
| --- | --- |
| `GET /health` | 健康检查 |
| `POST /ask` | `{text, session}` → `{ok, text, error, elapsed, tools}` |
| `POST /reset` | `{session}` 丢弃上下文 |
| `POST /stop` | `{session}` 中断任务 |

所有请求带 `X-DSH-Token` 头（或 `?token=`）。

## 安全

- 默认只监听 `127.0.0.1`，局域网访问不到
- 有口令校验，口令存在 `/root/.dsh-bridge-token`（600 权限）
- 它等价于「能在手机上执行命令」，别改到 `0.0.0.0` 除非清楚后果
